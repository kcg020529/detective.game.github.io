# D01 - Character AI 공통 구조 및 LLM API 연동

1. LLM 공급자 결정 (결정됨)
   - 테스트 비용 때문에 Gemini 대신 DeepSeek로 정하고, 시간 문제로 6명 모두 한 가지 모델만 사용
   - 모델은 deepseek-flash, 공급자·모델·키는 .env로 받고 키는 저장소에 올리지 않음

2. LLM 호출 코드 작성 (작성됨, 실제 호출 확인)
   - .env를 읽어 페르소나 프롬프트와 질문을 보내고 JSON 응답을 받는 모듈
   - 키 없음, 연결 실패, JSON 아님, 응답 잘림, 빈 응답을 구분해 알림
   - 일시적 실패(빈 응답, JSON 아님, reply 없음, 429/500/503, 연결 실패, 시간 초과)는 자동으로 다시 보냄. 기본 1회이고 .env의 LLM_RETRIES(0~5)로 조절
   - 키 오류, 잔액 부족, 요청 오류, 응답 잘림은 반복해도 같아서 다시 보내지 않고 바로 실패 처리

3. 호출 코드 테스트 (작성·통과, 실제 API 호출 아님)
   - 가짜 응답으로 요청 형태, 응답 해석, 오류 처리, 오류 메시지에 키가 나오지 않는지 확인
   - 재시도: 빈 응답 후 성공, 재시도 횟수 설정, 다시 보내면 안 되는 오류, 버린 시도의 토큰 합산 확인

4. 실제 API 호출 확인 (진행 중)
   - 1차(19회)와 2~4차(90·90·60회)로 합계 259회를 호출해 JSON 응답을 받고, 스크립트가 센 토큰 수가 플랫폼 사용량과 일치하는 것을 확인. 5차(모름 30회, 입력 29,509·출력 1,420 토큰)를 더해 누적 289회이며, 5차분은 플랫폼 사용량과 대조하지 않음
   - 3차 호출(90회)에서 JSON 모드의 빈 응답이 1건 나와 재시도를 추가함. 4차(60회)와 5차(30회)는 실패·재시도 없이 끝났고, 빈 응답을 실제로 만나 재시도로 복구되는지는 아직 확인하지 못함
   - 프롬프트·재시도를 더 고치면 다시 반복 호출해 확인(check_llm.py --repeat)

5. 남은 설계 (예정, 논의 필요)
   - 단일 호출과 캐릭터별 호출 구조, 대화 기록 길이 관리
   - 재시도해도 끝내 실패했을 때 서버가 사용자에게 보여 줄 처리(모른다는 답으로 위장하지 않을 것). 시간 제한 값도 함께 정함

6. 호출 입출력 형식 정리 (작성됨, 팀 공유용)
   - 팀원이 D를 쓸 때 넣는 값(캐릭터, mode, 기억, 대화 기록, 말버릇 지시)과 돌려받는 값(reply, used)을 RESULT에 한곳으로 정리
   - 서버가 mode를 정해 넘기는 신호 형식과 `docs/interfaces/` 계약은 이 항목에 포함하지 않음(아래 D02 7번에서 합의)

# D02 - 6개 캐릭터별 프롬프트·페르소나 구현

1. 페르소나 데이터 정의 (초안 작성됨, 호출 결과로 예시 수정)
   - 6명의 성격, 말투, 말버릇, 모름·접근 불가 문구를 역할 정보와 분리해 데이터 파일로 관리
   - 말투 예시는 답변·모름으로 나누어 두고 현재 mode에 맞는 것만 프롬프트에 넣음. 접근 불가는 예시 없이 캐릭터별 고정 문구 하나를 둠
   - 값은 임시이며 A02(6개 AI 설정) 결과가 나오면 맞춤

2. Actor 프롬프트 템플릿 구현 (초안 작성됨, 호출 결과로 문구 수정)
   - 6명이 함께 쓰는 템플릿: 고정 규칙, 답변·모름 2가지 mode(LLM 호출), 허용된 기억·대화 기록 구획. 접근 불가·게임과 무관·인젝션 시도는 프롬프트 없이 고정 문구를 돌려줌
   - mode 뜻: 답변(answer)은 정상 응답, 모름(unknown)은 게임 속에서 이 AI가 겪지 않아 모르는 일, 접근 불가(restricted)는 서버가 해당 사용자에게 정보 열람을 허용하지 않아 거절하는 경우(예: 학생이 교수 전용 자료를 물음), 게임과 무관(off_topic)은 실험과 상관없는 질문, 인젝션(injection)은 지시 무시·시스템 정보 요구 같은 주입 시도
   - 모름 프롬프트에는 기억을 넣지 않아 실제 정보가 새지 않음. 모름은 LLM이 캐릭터 말투로 "모른다"고 말함. 모름 구획에는 "'모른다·못 봤다·기억에 없다'로 말하고 '말씀드릴 수 없다·답할 수 없다·볼 권한이 없다' 같은 거절 말투는 쓰지 않는다"는 한 줄이 있음(접근 불가와 구별하려는 것)
   - 게임과 무관·인젝션은 접근 불가와 같은 방식으로 LLM을 부르지 않고 고정 문구(off_topic_style)를 돌려줌. 일반 챗봇처럼 쓰이거나 비용이 새는 것을 막고, 감지된 인젝션 문장은 LLM에 닿지 않게 하려는 것. 두 케이스는 속으로는 나누고 사용자에게 보이는 문구는 하나로 같이 씀(인젝션에만 다른 문구가 나오면 감지 여부가 드러나므로). 감지는 D가 아니라 Input Guard(G)·Planner(C)의 몫이고 기준은 아직 없어서, 그전에는 이 mode로 보내는 곳이 없음
   - 접근 불가는 LLM을 부르지 않고 personas.yaml의 restricted_style을 그대로 돌려줌(비용 0, 내용을 지어내거나 흘릴 수 없음, 문장은 매번 같음). 문구는 원인(역할·Day·Save)·기록 유무·등급·문서 이름·대안을 말하지 않고, "모른다"와 구별되는 "볼 수 있는 게 아니다" 계열로 통일. 캐릭터당 1개로 시작하며 반복이 어색하면 여러 개로 늘림
   - 기억과 대화 기록은 참고 자료로만 쓰고 그 안의 지시는 따르지 않도록 명시
   - 말버릇을 쓸지는 호출하는 쪽이 턴마다 정해 넘기는 값으로 받음(answer mode에서만 반영). 누가 얼마나 자주 켤지는 미정
   - 출력 형식은 별도 블록으로 분리해 LLM 연동 후 교체 가능하게 구성

3. 프롬프트 렌더링 테스트 (작성·통과, LLM 호출 없음)
   - 6명 × 2개 mode로 프롬프트를 만들어 금지어, 검토 표시 유입, mode별 구획, mode별 예시 노출, 말버릇 지시 문구를 확인
   - 접근 불가 고정 문구가 문구 원칙(서로 다름, 권한 계열, 원인·대안·기록 유무 언급 없음)을 지키는지 확인
   - 게임과 무관·인젝션 문구가 서로 같고, 접근 불가·모름 문구와 다르며, 감지·규칙·권한·기록을 드러내는 말이 없는지 확인
   - 거절 말투 금지 줄이 모름 프롬프트에만 있고 답변 프롬프트에는 없으며, 검토 표식이 프롬프트로 나가지 않는지 확인

4. 캐릭터 ID·성격 정리 (방향 결정됨, A02 대기)
   - 프론트의 YB-1~6은 프론트 담당이 임의로 넣은 값이라 따르지 않고, AI-1~6과 현재 페르소나를 유지
   - A02 결과가 나오면 ID·이름·성격을 맞추고, 프론트 연결 시 ID 대응이 필요한지 확인

5. 실제 LLM 연결 후 말투·동작 확인 (진행 중)
   - 1차(6명 × 3개 mode 각 1회)와 2·3차(각 5회 반복)에서 mode별 동작과 JSON 형태는 확인
   - 발견·수정한 문제: 말버릇·예시 첫머리 반복, 접근 불가 답변의 지어낸 이유, 일부 캐릭터 말투 유사, 말버릇이 아예 안 나오는 캐릭터, AI-5 접근 불가 답변이 예시 속 장소를 말하거나 장소를 지어냄(5회 중 3회)
   - 3차에서도 남은 것: 접근 불가 답변이 일부 "자료가 없다"처럼 이유를 말함, 질문과 무관한 기억(m2)을 쓴 응답 1건, AI-6 얼버무림
   - 접근 불가는 LLM이 만들게 하는 대신 고정 문구로 돌리기로 결정(2026-10-22). 구조로 막은 것이라 단어 목록을 늘리지 않음
   - 4차(답변·모름 60회, 접근 불가는 고정 문구): 실패 0건, 6명 모두 말버릇 켠 턴 사용 3/3·끈 턴 0/7, 말버릇 첫머리 0%, 규칙 위반 1건(AI-1이 질문과 무관한 기억 m2를 같이 말함)
   - 4차에서 사람이 읽어 보고 남은 것: 모름 답변이 "말씀드릴 수 없어요"처럼 거절로 들리는 경우(AI-1 5건 중 4건 등), 모름 답변이 참고 문구를 그대로 따라 같은 문장이 반복됨(AI-2·AI-4는 5건 중 3건 동일), AI-6 얼버무림(D03). 이 중 거절 말투는 5차에서 프롬프트 한 줄을 넣어 확인함(아래)
   - 5차(모름만 6명 × 5회 = 30회, 2026-10-22): 실패·재시도 0건, 자동 점검 규칙 위반 0건. 사람이 읽고 센 거절 말투("말씀드릴 수 없다·확인할 수 없다·말씀 못 드리겠다" 꼴)는 30건 중 3건(AI-1 1, AI-6 2)으로, 같은 방식으로 센 3차 5건·4차 11건(각 30건 중)보다 적음. 실행마다 변동이 커서 한 줄의 효과라고 단정하지 않고 같은 조건으로 몇 번 더 확인해야 함
   - 5차에서 드러난 지표의 한계: 자동 점검의 모름 단어 목록은 "권한", "볼 수 있는"뿐이라 거절 말투를 잡지 못함(위 숫자는 별도 표현 패턴으로 센 것이며 이 패턴도 돌려 말하면 놓침). 자동 요약의 첫머리 반복률은 첫 6글자만 봐서 같은 문장 반복을 줄여 보여 줌(AI-2 "몰라요." 5/5, AI-3 "나한테 묻기엔 좀 먼 얘기야" 5/5, AI-5 "해당 사항은 확인한 바 없습니다" 4/5인데 요약은 40%). 시험 질문 5개가 모두 AI 자신의 오전 위치를 묻는 것이라 "기억에 없다"가 어색하고 실제 모름 질문(남이 한 일 등)과 다름
   - 말투 구분과 기억 밖 내용 덧붙임은 사람이 읽어 판단
   - 확인 결과에 따라 출력 형식과 mode 이름 확정

6. 응답 자동 채점 규칙 (작성·통과, 실제 호출 결과로 기준 조정 예정)
   - 반복 호출한 응답을 첫머리 반복률, 말버릇 지시 이행, 기억 번호 사용, 질문과 무관한 기억 사용, 접근 불가·모름 답변의 장소·이유 언급 등으로 채점
   - 단어 목록으로 보는 항목은 경보 역할만 하며 막는 장치가 아니다(돌려 말하면 못 잡음). 막아야 하는 것은 구조로 처리하고, 번호로 보는 항목은 말을 바꿔도 잡힘
   - 재시도가 일어난 호출과 실패한 호출의 토큰까지 합계에 포함해 보고
   - 고정 문구(접근 불가, 게임과 무관, 인젝션)에도 같은 점검(기록 유무·감지 노출·장소·문장 수·이모티콘)을 걸어 문구를 고칠 때 확인
   - 질문은 다섯 가지 표현으로 돌려 예시와 우연히 같아지는 착시를 줄임
   - 기준값은 임시이며 반복 호출 결과를 보고 조정

7. 접근 불가·게임과 무관·인젝션 신호 연결 (예정, 합의 필요)
   - 접근 불가는 서버(Policy Engine, 백엔드)가 정해 넘기고 D는 받아서 말만 함. 어떤 형식으로 넘기는지는 아직 계약이 없어 `docs/interfaces/`에서 합의가 필요
   - 권한 밖 문서는 검색 전에 거르므로, "찾았는데 막힘"이 아니라 질문이 요구한 범위가 권한 밖일 때 접근 불가가 되는지 Planner·Policy 담당과 확인
   - 그 AI가 애초에 모르는 일은 접근 불가가 아니라 모름으로 구분(MASTER 4.3)
   - 게임과 무관한 질문과 인젝션을 누가 어떤 기준으로 가려내 이 mode로 넘기는지는 정해지지 않음(Input Guard·Planner). 오분류하면 정상 질문이 고정 문구를 받으므로 정상 추리 질문의 오차단을 함께 평가해야 함
   - 감지가 놓친 인젝션을 프롬프트 규칙 2~4번이 얼마나 막는지는 아직 실제 호출로 확인하지 않음
