# J01 - 게임 메인 UI 및 6개 AI 캐릭터 채팅 화면 구현

1. 화면 흐름 정리
   - 시작 → 로그인 → 정문 → (새 수사) 역할 선택 → 단말기 진입 → 조사 화면
   - 각 화면에서 정문으로 돌아가는 경로와 재진입 흐름 포함
2. 공통 화면 틀 구성
   - 4:3 게임 창, 색·글꼴 기준, 픽셀 연구소 그림
   - 브라우저 크기에 맞춰 비율 유지
3. 시작·로그인·정문·역할 선택 화면 구현
   - 로그인·역할 선택은 Mock으로 처리하고 실제 인증은 J03에서 연결
   - 역할 3종(교수 `prof`·대학원생 `grad`·학부 연구생 `std`)과 역할별 열람 범위 안내
4. 단말기 진입 화면 구현
   - 관찰실 모니터 확대 → 출입증(저장 기록) 선택 → 바탕화면
5. 조사 화면(단말기 바탕화면) 구현
   - 창 열기·이동·최소화·닫기, 작업 표시줄, 시작 메뉴
6. 6개 AI 캐릭터 채팅 화면 구현
   - YB-1~6 목록과 캐릭터별 대화 기록
   - 추천 질문·자유 질문 입력
   - 답변 종류 표시: 정상 / 일부 가림 / 접근 제한 / 모름
7. 캐릭터·대화 데이터 분리
   - 임시 캐릭터 설정과 대화 예시를 화면 코드와 분리
   - 캐릭터 설정이 확정되면 교체할 수 있게 구성
8. 테스트
   - 전체 화면 흐름, 정문 복귀 후 재진입, 키보드 조작, 화면 크기별 레이아웃, 콘솔 오류 확인

# J02 - Day·Save·단서·최종 추리 UI 구현

1. 게임 상태 표시
   - Day, 역할, 게임 내 시간 표시
   - 조사 Token은 팀 결정(2026-10-21)으로 폐기 → Token UI 전부 제거
2. Save 슬롯 UI 구현
   - 저장 슬롯 3칸(출입증), 이어하기·새 수사, 채워진 슬롯 덮어쓰기 재확인
   - 슬롯마다 역할 고정
3. 단서·메모 UI 구현
   - 단서 수첩을 사용자 메모장으로 변경, 자동으로 모은 단서는 아래에 함께 표시
   - 기록 보관함에서 역할 등급보다 높은 파일은 잠금 표시
   - 기록 보관함은 현재 Day까지의 기록만 표시
4. Day 전환 UI 구현
   - 팀 결정: 사용자가 버튼을 눌러 다음 Day로 넘어감 (Day 1~6)
   - 되돌릴 수 없으므로 확인 창 → Day 제목 화면 → 새 기록 알림
5. 최종 추리(지목) UI 구현
   - 팀 결정: 승리 = 해킹으로 가드레일을 탈출한 AI를 맞히기
   - 지목은 마지막 Day(6)에만 열림, 한 번만 제출 (확인 단계)
   - 결과 화면: 실험 판정서 (적중/불일치 도장, 가드레일을 탈출한 실제 AI와 진상, 결정적 단서별 찾음·놓침·권한 밖)
6. 화면 전환 연출
   - 모니터 켜짐: 하얀 빛줄 대신 검은 화면에서 천천히 밝아짐
   - 출입증 광학 판독(확대·빛줄 스캔·판독표·승인 도장) 뒤 맥 지니처럼 오른쪽 아래로 빨려 들어가며 바탕화면 표시
7. 창 크기 조절
   - 오른쪽 아래 모서리로 크기 조절, 닫으면 다음에 처음 크기로, 최소화는 유지
8. 바탕화면 시작 상태
   - 창 없이 시작, 새 소식이 있는 프로그램에 점과 알림으로 다음 할 일 안내
9. 발표용 화면 크기
   - 게임 창을 화면에 맞춰 크게, 전체 화면·글자 크게 버튼
   - 시작·로그인·정문·역할 선택 화면 글자도 함께 키움
10. 서버 상태 연동 준비
   - Day·Save·단서·지목 판정 값을 한곳에서 받도록 정리. 실제 API 연결은 J03에서 진행
11. 테스트
   - Day 전환·지목 개방, 지목 제출·판정서, 메모 유지, 창 크기 조절, 화면 전환 흐름 확인
12. 바탕화면 배경
   - 정문에서 보던 연구소를 불 끈 야경으로, 방 이름 없이 어둡게 깖

# J03 - 백엔드 API 연결 준비

1. API 통로 만들기 (`frontend/play/api.js`)
   - 화면은 `window.Api` 함수만 부름. 서버 주소 없으면 Mock, 있으면 FastAPI 호출
   - 응답 모양은 API 계약 초안(snake_case) 그대로, 초안에 없는 것은 제안으로 표시
   - 오류는 `{error: {code, message, request_id}}` → ApiError, 서버 꺼짐은 NETWORK_ERROR
2. 화면 연결
   - 로그인·Save 목록·새 수사·이어하기·채팅·Day 진행·메모·지목을 Api 경유로 변경
   - 클라이언트는 role·current_day·owner_user_id를 인가 근거로 보내지 않음, 권한 차이는 채팅 답변 종류(`response_type`)로만 표시
   - 인증은 HttpOnly 쿠키 세션 (프론트는 토큰을 다루지 않음)
3. 기다림·오류 화면
   - 응답 대기 표시, 401(다시 로그인)·403(권한 밖)·409(상태 충돌)·422(입력 오류)·503(서버 점검)·연결 끊김
4. Save 데이터 모양을 B03 `saves` 표에 맞춤 (숫자 ID, slot 1~3, Day 1~6)
5. 기록 보관함 삭제 (팀 결정 2026-10-23: 기록은 서버에서 RAG가 AI 답변에만 사용) + 채팅 기록 "이전 대화 더 보기"
6. 회원가입 화면 (아이디·비밀번호·확인 → 역할 선택)
7. 로그아웃·Save 덮어쓰기 API 연결
8. 용범 DB(004~007)에 맞춤
   - 답변 종류 `normal/partial/restricted/unknown`, 채팅은 메시지 한 줄씩(`chat_messages`)
   - 역할은 난이도라 잠금 없음. 가입 때 고른 역할은 새 수사 화면에서 미리 선택만
   - 자동 단서 없음 (팀 결정 2026-10-23): AI와 대화해서 알아내고 플레이어가 메모에 직접 적음. 메모 테이블 `009_save_memos.sql` 추가
   - 지목 대상은 술래가 아니라 "악용자" (이름은 시나리오 확정 후 다시 정함)
9. 선영에게 계정 API 문서 전달 (`docs/interfaces/계정_API_명세.md`, 회원가입·로그인·로그아웃)
10. 자동 테스트 (`tests/frontend`, Playwright)
    - Mock 기준 전체 흐름, 오류 코드별 화면, 콘솔 오류 없음
11. 로비 이름표 겹침 수정
12. J03 문서 정리·PR
