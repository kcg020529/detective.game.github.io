# J01 - 게임 메인 UI 및 6개 AI 캐릭터 채팅 화면 구현

1. 화면 흐름 정리
   - 시작 → 로그인 → 정문 → (새 수사) 역할 선택 → 단말기 진입 → 조사 화면 흐름으로 구현
   - 조사 화면에서 정문 복귀, 정문에서 다시 이어하기까지 확인
2. 공통 화면 틀 구성
   - 빌드 없는 정적 HTML/CSS/JS. 외부 의존성은 Pretendard 글꼴 CDN 하나
   - 코드: `frontend/index.html`, `frontend/style.css`, 픽셀 연구소 그림은 `frontend/app.js` 캔버스
3. 시작·로그인·정문·역할 선택 화면 구현
   - 화면 구현 완료, 인증은 Mock (아이디·비밀번호가 비어 있지 않으면 통과, 계정 만들기는 안내 문구만)
   - 실제 로그인·로그아웃 API 연결은 J03에서 진행
   - 역할을 MASTER 5.1 확정 명칭으로 교체: 교수 `prof` / 대학원생 `grad` / 학부 연구생 `std` (이전 관리자·보안 분석가·개발자)
     - 역할 키, 화면 이름표, 조작 안내, 저장 슬롯 예시, 기록 보관함 등급·대화 예시 문구까지 함께 변경 (`frontend/index.html`, `frontend/app.js`, `frontend/play/c.js`, `frontend/play/data.js`)
     - 역할별 열람 범위·등급 순서(교수 > 대학원생 > 학부 연구생)는 기존 그대로. 실제 권한 매트릭스는 F 확정 후 반영
     - 검증: `node --check` 3개 파일 통과, 헤드리스 Chrome에서 역할 선택 화면(값 `prof`·`grad`·`std`)과 `?skip=1` 조사 화면 렌더링 확인, 콘솔 오류 없음. 옛 역할 이름 잔여 검색 0건
4. 단말기 진입 화면 구현
   - 모니터 확대 → 화면 켜짐 → 출입증 3장 중 선택 → 리더기 확인 → 바탕화면
   - 이어하기·새 수사(빈 출입증, 덮어쓰기 재확인) 두 경로 모두 동작
   - 코드: `frontend/play/c.js` (`enter`). 이전 리눅스 터미널 화면 코드는 `app.js`에 남아 있지만 사용하지 않음
5. 조사 화면(단말기 바탕화면) 구현
   - 창 드래그·맨 앞으로·최소화·닫기, 작업 표시줄, 시작 메뉴 구현
   - 코드: `frontend/play/c.js` (`mount`), `frontend/play/c.css`
6. 6개 AI 캐릭터 채팅 화면 구현
   - YB-1~6 메신저, 추천 질문·자유 질문, 답변 종류 4가지 색·이름표 표시
   - 답변은 Mock (미리 넣은 예시 대화, 자유 질문은 키워드로 예시 답 선택). LLM·RAG 연결 없음
7. 캐릭터·대화 데이터 분리
   - 캐릭터·대화·단서·기록 파일 예시를 `frontend/play/data.js`로 분리
   - 캐릭터 성격·대화 내용은 임시값. A02(6개 AI 설정) 결과가 나오면 교체 필요
8. 테스트
   - 로컬에서 헤드리스 Chrome 스크립트로 이어하기·새 수사·정문 복귀·재진입 3회 확인, 콘솔 오류 없음
   - 1440×1000, 800×600 화면 캡처로 레이아웃 확인
   - 테스트 스크립트·로그·캡처는 저장소에 올리지 않음 (자동 테스트 미구성)

# J02 - Day·Save·단서·최종 추리 UI 구현

1. 게임 상태 표시
   - 작업 표시줄에 Day·시간·역할 표시 (값은 Mock)
   - 조사 Token 표시·차감·소진 처리와 데이터(`MAX_TOKENS`, `tokens`, `maxTokens`) 모두 제거. 질문 횟수 제한 없음
2. Save 슬롯 UI 구현
   - 출입증 3장 형태. 이어하기·새 수사·덮어쓰기 재확인 동작, 카드에 `Day n/6 · 단서 n` 표시
   - 저장은 브라우저 메모리에만 있음 (새로고침하면 예시 기록으로 초기화)
   - 코드: `frontend/app.js` (`saves`, `MAX_DAY`), `frontend/play/c.js`
3. 단서·메모 UI 구현
   - 단서 수첩 위쪽은 줄 노트 모양 메모 칸(`save.memo`, Day가 바뀌어도 유지), 아래쪽은 자동으로 모은 단서(Day별)
   - 기록 보관함은 `record.day ≤ 현재 Day`인 파일만 표시, 잠금·접근 거부는 화면 표시용 (실제 권한 판정은 서버 쪽, 미연결)
4. Day 전환 UI 구현
   - 작업 표시줄 오른쪽 "다음 Day로" 버튼 → 확인 창("돌아올 수 없음") → 검은 화면에 Day 번호 → 새 기록 알림
   - Day 6에서는 "마지막 Day"로 바뀌고 비활성
   - 코드: `openDayDialog`, `advanceDay` (`frontend/play/c.js`)
5. 최종 추리(지목) UI 구현
   - 지목 아이콘·작업 표시줄·시작 메뉴 항목은 Day 6에만 보임 (`appOpen`)
   - 제출 → 창 안에서 한 번 더 확인 → 확정 후 변경 불가, 지목 창에서 "판정서 보기"로 다시 열기
   - 판정서: 종이가 올라오고 적중/불일치 도장, 가려진 진상이 걷히고 결정적 단서 4개를 찾음·놓침·권한 밖으로 표시
   - 정답·진상·결정적 단서는 예시값(`data.verdict`). A 파트 시나리오 확정 후 서버 응답으로 교체
6. 화면 전환 연출
   - 모니터 켜짐: 출입증 화면이 검은 화면에서 0.9초 동안 밝아지며 제자리로 (`c-screen-in`)
   - 출입증 판독: 나머지 카드는 물러나고 고른 카드 확대 → 빛줄 스캔 → 판독표(역할·Day·단서·열람 범위) → 승인 도장 (`scanBadge`)
   - 바탕화면 전환: 승인 직후 모니터를 html2canvas(CDN, 1.4.1)로 그림으로 뜨고, canvas에 1px 줄 단위로 다시 그리며 S자 깔때기를 따라 오른쪽 아래로 빨려 들어감 (`genieCanvas`, 약 0.9초)
   - 그림을 뜨지 못하면 matrix3d 원근 변형으로 대체 (`genie`)
   - 동작 줄이기 설정에서는 연출 없이 바로 전환
7. 창 크기 조절
   - 창 오른쪽 아래 빗금을 끌어 조절, 최소 22×19cqw, 바탕화면(작업 표시줄 위) 밖으로 못 나감
   - 닫기는 다음에 열 때 처음 크기로, 최소화는 크기·위치 유지. 기록 보관함 기본 크기 확대
8. 서버 상태 연동 준비
   - 부분 구현. Day·Save·메모는 `frontend/app.js`의 `saves`, 캐릭터·단서·기록·판정은 `frontend/play/data.js`
   - API 연결은 J03에서 진행
9. 버그 수정
   - 바탕화면에서 "세션 선택으로" 이동 뒤 바탕화면 시계가 작업 표시줄을 찾다 오류가 나던 문제 수정 (시계 정지 + 방어 코드)
10. 테스트
   - 로컬 헤드리스 Chrome(Playwright) 스크립트로 확인, 콘솔 오류 없음
   - 시작 → 로그인 → 이어하기 → 켜짐 → 판독 → 바탕화면, 세션 전환, 정문 → 새 수사 → 빈 슬롯
   - Day 2 → 6 전환 시 지목 개방·알림, 오답 지목 → 판정서 → Esc 닫기 → 다시 열기, 메모 유지, 창 크기 조절·닫기 복원
   - 전환 연출 프레임 간격 중앙값 약 16.7ms(60fps)
   - 테스트 스크립트·캡처는 저장소에 올리지 않음 (자동 테스트 미구성)
