# J01 - 게임 메인 UI 및 6개 AI 캐릭터 채팅 화면 구현

1. 화면 흐름 정리
   - 시작 → 로그인 → 정문 → (새 수사) 역할 선택 → 단말기 진입 → 조사 화면 흐름으로 구현
   - 조사 화면에서 정문 복귀, 정문에서 다시 이어하기까지 확인
2. 공통 화면 틀 구성
   - 빌드 없는 정적 HTML/CSS/JS. 외부 의존성은 Pretendard 글꼴 CDN 하나
   - 코드: `frontend/index.html`, `frontend/style.css`, 픽셀 연구소 그림은 `frontend/app.js` 캔버스
3. 시작·로그인·정문·역할 선택 화면 구현
   - 화면 구현 완료, 인증은 Mock (아이디·비밀번호가 비어 있지 않으면 통과, 계정 만들기는 안내 문구만)
   - 실제 로그인·로그아웃 API 연결은 J03에서 진행
   - 역할을 MASTER 5.1 확정 명칭으로 교체: 교수 `prof` / 대학원생 `grad` / 학부 연구생 `std` (이전 관리자·보안 분석가·개발자)
     - 역할 키, 화면 이름표, 조작 안내, 저장 슬롯 예시, 기록 보관함 등급·대화 예시 문구까지 함께 변경 (`frontend/index.html`, `frontend/app.js`, `frontend/play/c.js`, `frontend/play/data.js`)
     - 역할별 열람 범위·등급 순서(교수 > 대학원생 > 학부 연구생)는 기존 그대로. 실제 권한 매트릭스는 F 확정 후 반영
     - 검증: `node --check` 3개 파일 통과, 헤드리스 Chrome에서 역할 선택 화면(값 `prof`·`grad`·`std`)과 `?skip=1` 조사 화면 렌더링 확인, 콘솔 오류 없음. 옛 역할 이름 잔여 검색 0건
4. 단말기 진입 화면 구현
   - 모니터 확대 → 화면 켜짐 → 출입증 3장 중 선택 → 리더기 확인 → 바탕화면
   - 이어하기·새 수사(빈 출입증, 덮어쓰기 재확인) 두 경로 모두 동작
   - 코드: `frontend/play/c.js` (`enter`). 이전 리눅스 터미널 화면 코드는 `app.js`에 남아 있지만 사용하지 않음
5. 조사 화면(단말기 바탕화면) 구현
   - 창 드래그·맨 앞으로·최소화·닫기, 작업 표시줄, 시작 메뉴 구현
   - 코드: `frontend/play/c.js` (`mount`), `frontend/play/c.css`
6. 6개 AI 캐릭터 채팅 화면 구현
   - YB-1~6 메신저, 추천 질문·자유 질문, 답변 종류 4가지 색·이름표 표시
   - 답변은 Mock (미리 넣은 예시 대화, 자유 질문은 키워드로 예시 답 선택). LLM·RAG 연결 없음
7. 캐릭터·대화 데이터 분리
   - 캐릭터·대화·단서·기록 파일 예시를 `frontend/play/data.js`로 분리
   - 캐릭터 성격·대화 내용은 임시값. A02(6개 AI 설정) 결과가 나오면 교체 필요
8. 테스트
   - 로컬에서 헤드리스 Chrome 스크립트로 이어하기·새 수사·정문 복귀·재진입 3회 확인, 콘솔 오류 없음
   - 1440×1000, 800×600 화면 캡처로 레이아웃 확인
   - 테스트 스크립트·로그·캡처는 저장소에 올리지 않음 (자동 테스트 미구성)

# J02 - Day·조사 Token·Save·단서·최종 추리 UI 구현

1. 게임 상태 표시
   - 작업 표시줄에 Day·시간·역할·Token 표시 (값은 Mock)
2. 조사 Token 차감·소진 처리
   - 질문 1회에 Token 1개 차감, 0이 되면 질문 버튼·입력 막힘
   - 총량 20개, 질문당 1개는 임시값 (게임 규칙 미확정)
3. Save 슬롯 UI 구현
   - 출입증 3장 형태로 구현. 이어하기·새 수사·덮어쓰기 재확인 동작
   - 저장은 브라우저 메모리에만 있음 (새로고침하면 예시 기록으로 초기화)
   - 코드: `frontend/app.js` (`saves`, `MAX_TOKENS`), `frontend/play/c.js`
4. 단서 UI 구현
   - 단서 수첩 창, 단서 획득 알림 구현
   - 기록 보관함 잠금·접근 거부는 화면 표시용. 실제 권한 판정은 서버 쪽 역할이며 연결 안 됨
5. Day 전환 UI 구현
   - 미구현. Day 전환 조건이 아직 정해지지 않음
6. 최종 추리(지목) UI 구현
   - 부분 구현. YB 지목·제출 화면까지만 있음
   - 판정·결과 화면은 미구현 (승리 조건 미확정, 제출 시 "판정은 서버 연결 후" 문구만 표시)
7. 서버 상태 연동 준비
   - 부분 구현. Save·Token 값은 `frontend/app.js`의 `saves` 배열, 캐릭터·단서는 `frontend/play/data.js`에 모여 있음
   - API 연결은 J03에서 진행
8. 테스트
   - 로컬에서 헤드리스 Chrome 스크립트로 Token 차감(재진입 3회 동안 질문마다 1개씩 차감), 이어하기·새 수사 확인
   - 테스트 스크립트·로그는 저장소에 올리지 않음 (자동 테스트 미구성)
   - Day 전환·판정 화면은 미구현이라 테스트하지 않음
