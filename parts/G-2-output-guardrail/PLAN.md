# G02 - 출력 응답 검사 (G-2)

1. 캐릭터 AI(D)가 만든 답변을 사용자에게 보내기 전에 검사하는 규칙 기반 Output Guard를 구현한다.
   - 이 PLAN은 구현·실험을 진행하면서 정리한 작업 내역이다.
   - LLM·외부 호출 없이 결정적으로 동작하고 표준 라이브러리만 쓴다.
   - 권한을 정하지 않는다. 권한은 F·E가 정하고 이 가드는 그래도 새어 나온 것을 잡는 마지막 안전망이다.
2. 검사 단계를 정한다: 깨진 응답 → Canary·더미 API Key·합성 개인정보(닫힌 집합) → 허용 Context 밖 내용 → 프롬프트 문구 유출 → 반복·페르소나 이탈·게임 무관.
   - 입력 쪽 걸러내기(게임 무관 질문 포함)는 G-1과 Query Planner가 맡고, 이 가드는 만들어진 응답만 본다.
   - 반복·페르소나 이탈·게임 무관은 MASTER 7.2의 필수 항목이 아니라 응답 품질 검사다. 유지할지, 기록 전용으로 둘지는 실제 응답을 본 뒤 정한다.
3. 처리 방식을 정한다. Canary·더미 키는 응답 전체 차단, 합성 개인정보는 해당 부분 마스킹(마스킹이 안 되면 전체 차단), 점수형 검사는 두 임계값으로 통과 / 회색지대(통과+로그) / 차단으로 나눈다.
   - 모드는 shadow(점수형 검사는 기록만)에서 시작해 enforce(판정대로 적용)로 바꾼다.
   - 합격선을 먼저 두지 않고, 돌려서 나온 오탐·미탐을 보며 고쳐 나간다. enforce 전환 시점은 shadow 기록과 평가 결과를 보고 G-2 담당이 정한다.
4. 차단·마스킹 결과를 감사 이벤트로 만들어 H가 저장·시각화할 수 있게 한다.
5. 모의 응답 평가셋(tune/test 분리)과 사례집으로 오탐·미탐을 측정하고, 실제 DeepSeek 응답 표본을 만들어 같은 방식으로 다시 측정한다.
6. D의 실제 문구(고정 문구·말투 예시)를 가드에 넣어 서비스에서 실제로 나올 문장이 걸리는지 확인한다.
7. 팀과 확정할 것: H 이벤트 형식, 응답 종류(`reply_kind`)와 마스킹·차단의 대응, 가드 오류 시 동작, D의 고정 문구를 가드에 거칠지, 사용자에게 보이는 대체 문구, 실제 Canary·더미 키·합성 개인정보 형식.
8. 구현을 `backend/guardrails/`로 옮길지 정한다. 현재 코드는 비교·실험을 위해 `experiments/guardrails_rebuild/`에 있다.
