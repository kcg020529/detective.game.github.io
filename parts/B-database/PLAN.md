# B01 - 게임 기록 스키마

1. A01 메타데이터와 A02 JSON 원본에 대응하는 MariaDB 기본 테이블을 설계한다.
2. 직접 참여·목격·엿듣기 AI 목록을 관계 테이블로 분리하고, 데이터셋과 기록 ID로 연결한다.
3. 픽스처의 역할 허용 목록을 저장하되 최종 보안 등급 정책은 후속 협의한다.
4. Docker 초기 SQL 경로에 테이블 정의를 작성하고 매핑·제약·미구현 범위를 기록한다.
5. 후속 작업으로 MariaDB 실행 검증과 JSON 적재 도구, 추가 보안 메타데이터를 구현한다.

# B02 - 유저 테이블

1. 로그인·회원가입용 `users` 테이블을 작성한다.
2. 합의한 `user_id`, `username`, `password_hash`, `created_at` 네 필드만 두고 아이디 중복을 제한한다.
3. 비밀번호 해시 생성·검증과 인증 API는 백엔드에서 후속 구현한다.

# B03 - Save 테이블

1. 사용자별 최대 세 개 슬롯을 저장하는 `saves` 테이블을 작성한다.
2. Save ID·소유 사용자·슬롯 번호·역할·현재 Day·생성 시각·마지막 플레이 시각을 저장한다.
3. 사용자 외래키, 슬롯 중복 방지 및 슬롯·역할·Day 유효 범위 제약을 적용한다.

# B04 - 대화 및 권한 테이블

1. Save·AI별 대화 이력을 저장하는 `chat_messages`를 작성한다.
2. 계정별 허용 역할을 저장하는 `user_roles`를 작성한다.
3. 문서·역할별 5단계 공개 수준을 저장하는 `document_permissions`를 작성한다.
4. 단계별 허용 필드와 기존 역할 목록 테이블의 대체 관계를 문서화한다.

# B05 - 장소 메타데이터

1. A01의 일곱 장소와 location_ids를 저장할 장소 목록·기록별 장소 관계를 정의한다.
2. data/ 원본 경로, Setup의 장소 의미와 공개 수준별 제공 범위를 스키마 안내에 반영한다.

# B06 - MariaDB 적재 도구

1. data/ JSON을 읽고 메타데이터·관계를 검증하는 Python CLI를 작성한다.
2. DB 환경변수와 dry-run을 지원하고 본문·AI·장소·권한을 단일 트랜잭션으로 upsert한다.
3. 공개 수준과 예전 테스트 데이터의 장소 누락은 명시적 옵션으로 처리한다.
4. 공통 규칙의 별도 저장 테이블을 추가하고 반복 적재·rollback 처리 및 검증 실패를 테스트한다.
