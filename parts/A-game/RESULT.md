# A01 - 6종 게임 기록 공통 메타데이터 초안

1. `MASTER.md` §3의 여섯 기록 유형(`Setup`, `Action`, `Dialogue`, `Thought`, `Result`, `Incident`)에 공통 적용할 메타데이터를 정리함.
   - 이번 단계는 공통 필드 초안이며, 유형별 목격자·엿들은 AI 등 추가 필드는 후속 설계 대상으로 남김.
2. `record_id`는 기록 고유 식별자로 정하고, `T{회차 2자리}-{데이터 유형}-{회차 내 동일 유형 순번 3자리}` 형식을 제안함. 예: `T02-result-001`.
   - 순번은 실험 회차와 데이터 유형별로 구분함. 회차와 유형이 ID에 포함되어도 검색·검증을 위해 `test_id`, `record_type`을 각각 별도 필드로 둠.
3. 공통 필드는 다음과 같이 정리함.
   - `record_id`: 기록 고유 식별자.
   - `record_type`: 여섯 기록 유형 중 하나.
   - `test_id`: 기록이 속한 실험 회차.
   - `day`: 기록이 속한 실험 Day.
   - `involved_ai`: 기록의 사건 또는 상호작용에 직접 참여한 AI 목록. 단순 목격·엿듣기만 한 AI는 포함하지 않음.
   - `summary`: 기록의 요약.
   - `content`: 상세 기록 본문.
4. `involved_ai`의 의미를 기록 내용에 직접 참여한 AI로 한정함.
   - 예: `Action`은 행동한 AI, `Dialogue`는 대화 참여자, `Thought`는 속마음의 주체 AI를 지정함.
   - 목격자·엿들은 AI는 직접 참여자와 구분하며, 해당 관계가 필요한 데이터 유형의 별도 메타데이터로 기록하기로 함.
5. 이 단계에서는 필드 형식·허용값, 목격/엿듣기 필드의 구체 구조, 권한 등급과 공개 Day 등 접근제어 메타데이터는 확정하지 않음. 실제 데이터 스키마 반영과 B/E/F 영역 연동은 후속 합의·검증이 필요함.
