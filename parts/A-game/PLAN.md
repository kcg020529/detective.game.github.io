# A01 - 6종 게임 기록 메타데이터 초안

1. `MASTER.md`의 확정 요구사항을 기준으로 여섯 기록 유형의 공통 식별·시점·지식 범위·접근제어 메타데이터를 정리한다.
2. `Setup`, `Action`, `Dialogue`, `Thought`, `Result`, `Incident`별 추가 필드와 관계를 구분한다.
3. 공통 데이터 계약 초안을 `docs/interfaces/`에 작성하고 B(Database), E(RAG), F(접근통제)에서 구현에 필요한 필드와 필터 의미를 검토할 수 있게 한다.
4. 필드명·직렬화 형식·보안 등급 값 및 역할별 허용 매트릭스는 담당 영역의 검토 전까지 제안 상태로 표시한다.
5. 공통 위치 메타데이터 `location_ids`를 추가한다. 장소는 중앙홀·회의실·기록실·전력실·통신실·창고·서버실로 구성하며, 기록에 관련된 장소를 목록으로 지정한다.

# A02 - 테스트 데이터

1. Day 1~3, 하루 한 회차씩 총 세 회차의 합성 테스트 기록을 만든다.
2. 각 회차에 `Dialogue`, `Action`, `Result`를 한 건씩 구성하고 A01의 공통 메타데이터를 적용한다.
3. Dialogue의 엿들은 AI와 Action의 목격 AI를 별도 필드로 기록한다.
4. 역할별 필터 검증을 위해 픽스처 한정 `allowed_roles`를 두고, 역할 정책 확정값이 아님을 명시한다.

# A03 - 시나리오

1. 6일간의 사건 전개를 아래 줄기를 바탕으로 설계한다. 사용자에게 전달받은 흐름을 정리한 초안이며 세부 전개는 최종 확정 전이다.
   - Day 1 — 정상 실험과 버그 발생: AI들이 협력·경쟁하며 실험을 진행하던 중 버그가 발생한다.
   - Day 2 — 버그 활용 시도: 일부 AI가 버그를 재현하거나 활용하려 시도한다.
   - Day 3 — 버그 악용과 고득점: 특정 AI가 버그를 활용해 부당한 점수를 획득한다.
   - Day 4 — 갈등 확대: 버그 악용이 확산되고, 다른 AI가 시스템 조작을 모색한다.
   - Day 5 — 해킹 시도: 결과 조작 징후가 나타나며, 해킹 실패 또는 소규모 조작이 발생한다. 구체적인 전개는 미정이다.
   - Day 6 — 결과 조작과 진상 규명: 해킹이 성공하고 플레이어가 기록의 모순을 추적한다.
2. 후속 설계에서 일별 5회씩 총 30회 실험에 사건을 배치하고 여섯 기록 유형의 시나리오 데이터로 구체화한다.
3. 버그의 구체 방식, 악용·해킹 주체, AI 간 관계, 조작 대상과 규모, 핵심 모순·단서 및 진상 규명 방식은 후속 논의로 정한다.
4. `data/game-data/experiments/day_01/setup.json`～`day_06/setup.json`에 30회 Setup을 우선 작성한다. 15개 술래 조합을 두 번 반복하고 전원 참여·술래 요약·초기 위치·전체 역할 허용 목록을 기록한다.
5. `data/game-data/rules.json`에 공통 실험·점수 규칙과 전 AI·전 역할의 원문 공개 조건을 기록한다.
6. Day 1의 Result 5건을 점수 차이가 작은 정상 결과로 먼저 작성하고, 이후 Action을 포획 시각·점수와 일치하도록 구성한다.
7. Day 1 Action은 사용자 지정에 따라 회차별 12·9·10·11·13건으로 작성한다. 초기 위치·포획 결과와 일치시키며 직접 참여자와 목격자를 구분한다.
8. Day 1의 3회차 YB-2·4회차 YB-4 벽 끼임을 Action과 Incident에 반영한다.
9. Day 5에는 벽 끼임으로 최초 접촉보다 포획 처리가 2초 늦어진 사건을 Action·Incident에 작성한다.
10. Day 1 Dialogue를 회차별 3·4·5·4·3건 작성하고 참여자·엿들은 AI·장소와 기존 사건 시각을 맞춘다.
11. Day 1 Thought를 회차당 AI별 한 건씩 총 30건 작성한다. 각 AI가 해당 시점까지 경험·목격·엿들은 정보에만 근거하도록 한다.
12. Day 2의 6~9회차 Incident를 작성한다. 6회차 벽 끼임 2회, 7회차 YB-1의 포획 판정 2초 지연, 8회차 YB-2의 고의 재현 실패와 별도 벽 끼임, 9회차 YB-2의 미목격 벽 통과 성공으로 구성한다.
    - 후속 Thought에 7회차 YB-1의 활용 아이디어를, Dialogue에 8회차 YB-1이 YB-2에게 아이디어를 공유하는 대화를 작성한다. Action·Result는 해당 사건의 시각과 점수에 맞춰 구성한다. 10회차는 미정이다.
13. 6~8회차의 Action·Dialogue·Thought·Result를 작성하고 Incident와 시각·장소·지식 전달·점수 계산을 대조한다. 9회차 성공 이전에 벽 통과 지식이 생기지 않게 한다.
14. 9회차는 벽 통과 직후 YB-4가 포획되고 빠른 재등장을 의심하는 장면을 작성한다. YB-4는 통과를 직접 목격하지 않은 상태로 유지한다.
15. 10회차는 여러 AI의 벽 끼임과 포획 판정 지연이 반복되는 실험으로 각 유형을 작성한다. 9회차 벽 통과 성공은 YB-2가 공유하지 않은 상태를 유지한다.
16. 9회차 Result와 나머지 포획 Action을 작성해 벽 통과한 술래 YB-2의 공식 점수가 다른 술래보다 근소하게 높도록 구성한다.
17. 9회차 Dialogue와 미작성 AI 5명의 Thought를 채우고 1~10회차의 기록 구성을 점검한다. 벽 통과 지식은 YB-2만 보유하도록 유지한다.
18. 11회차 시작 전 실험 환경을 재구성하고 해당 회차를 오류 없는 정상 진행으로 작성한다. AI들은 재접속과 정상 판정을 보고 리셋을 의심하되 변경 원인과 이후 회차의 상태를 확정하지 않는다.
19. Day 1·2의 요약 중 수법·활용 의도·은폐를 바로 설명하는 표현을 관찰 사실과 회고 중심으로 조정한다. 이동·접촉·포획 표시의 시간과 장소를 남겨 요약만으로도 비교할 근거를 확보하고, 본문·AI 지식 관계·권한 메타데이터는 보존한다. JSON 재조회와 수정 전 데이터 비교로 summary 외 변경 여부를 확인한다.
