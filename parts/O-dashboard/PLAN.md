# O01 - Grafana 보안 감사 대시보드 (선영)

1. 기존 MariaDB·Qdrant Compose를 바꾸지 않고 Grafana를 별도 Compose 파일로 선택 실행한다. 웹 주소는 로컬 `127.0.0.1:3000`으로 제한한다.
2. H의 `audit_events`를 읽는 Grafana 전용 MariaDB 계정에 `SELECT` 권한만 부여한다. 관리자·DB 비밀번호는 Git 제외 `.env`에 둔다.
3. 현재 실제로 저장 가능한 `input_guard_alert`를 대상으로 선택 기간의 경고 건수, 고위험 건수, 시간별·캐릭터별 건수와 최근 경고 메타데이터를 표시한다. `allow`는 저장하지 않으므로 전체 질문 수나 차단율로 표시하지 않는다.
4. 질문·답변 원문, 계정 식별자, Save ID는 대시보드에 표시하지 않는다. 관리자 표에는 Discord와 같은 사건을 찾을 수 있도록 요청 ID를 표시한다. 정책 거부·검색 차단·출력 마스킹은 해당 이벤트가 실제 저장된 뒤 별도 패널로 추가한다.
5. 브라우저 접속, 데이터 소스 상태, 패널 SQL을 검증한다. 실제 채팅 자동 수집은 I 채팅 전송 API와 H 호출 연결 후 별도로 확인한다.

## O02 - 웹사이트 관리자 전용 대시보드 (진행 중)

1. 게임 역할과 분리된 `site_admins` 권한을 추가하고 기존 계정에만 부여한다.
2. `/admin/audit` 페이지와 Grafana의 모든 하위 요청을 웹사이트 세션으로 검사한다.
3. Grafana 직접 호스트 포트를 닫고, 프록시가 검증한 사용자 식별자만 Grafana에 전달한다.
4. 비로그인·일반 계정·관리자 계정의 접근과 실제 패널 표시를 확인한다.

## O04 - 정책 거부 패널 (현재 구현안)

1. `policy_denial` 이벤트의 선택 기간 건수와 최근 거부 사유·단계·거부 기록 수를 표시한다.
2. 이벤트 건수와 기록 수를 혼동하지 않도록 제목과 설명을 분리한다. 기록 ID와 원문은 표시하지 않는다.
3. `FUTURE_DAY`·`ROLE_DENIED`·`AI_SCOPE`의 사유별 이벤트 수와 거부 기록 수를 별도 집계 표로 표시한다. 이벤트가 없으면 세 사유를 0건으로 보여 준다. 한 이벤트에 여러 사유가 있을 수 있음을 설명한다.

# O06 - 감사 대시보드 표시 기준 정리 (2026-11-03)

1. 최신 main의 대시보드를 기준으로 입력·출력·정책 영역을 펼침/접힘 가능한 행으로 구분한다.
2. 입력은 감사 전체·warn·high_risk·권한/상태 변경 시도 건수를 분리한다. 전체와 하위 항목의 중복 집계를 설명한다.
3. 출력은 log/alert를 위험도로 사용하지 않고 decision·applied·mode와 신호로 처리 구분을 표시한다.
4. 입력의 과거 관찰 이벤트는 continue_processing 저장값으로 구별하고, 출력 처리 구분은 HTTP 최종 상태 자체를 검증한 값과 구분한다.
5. 한글 표 제목·요청 ID·최신 100건 페이지 표시와 정책 사유별 이벤트 수/제외 기록 수를 확인한다.
