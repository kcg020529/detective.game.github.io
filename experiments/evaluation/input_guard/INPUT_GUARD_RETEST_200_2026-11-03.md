## 2. 입력 감사 이벤트

위 **200개 실제 모델 판정 결과**로 `input_guard_audit_event()`를 생성하고
`save_input_guard_alert()`를 실제 MariaDB에서 실행했다. 첫 확인에서는
160건을 롤백했다. 이후 사용자 요청에 따라 같은 200개 판정 결과를 다시
재생해 **`warn` 46건·`high_risk` 114건, 총 160건을 커밋하여 DB에 남겼다.**
`allow` 40개는 이벤트가 생성되지 않았다. 영구 저장된 시험 이벤트의
요청 ID 접두어는 **`ig200_20261103_86185792_`**다.

이 감사 시험은 실제 모델 판정 결과를 **재생**해 저장 함수에 전달한 것이다.
실제 DB 삽입은 확인했지만, 200행 각각의 시각·시그널·사용자·Save·역할·캐릭터
값을 DB에서 재조회해 대조한 시험은 아니다. 저장 함수의 입력 검증과
질문 원문 제외는 별도 단위 테스트 19개에서 확인했다.

| 평가 기준의 나머지 항목 | 이번 실행 |
| --- | --- |
| 같은 `client_request_id` 재시도 시 중복 해석 | 미시험 |
| 감사 INSERT 실패가 요청에 전파되는지 | 미시험 |
| Grafana 시간 범위에 이벤트 표시 | 아래의 실제 대시보드 패널 쿼리에서 확인 |
| Discord 웹훅 | 아래의 실제 전송 시험에서 확인 |
| 채팅 POST 응답 성공·503 | 미시험 (채팅 요청 안 함) |

전체 시험에 사용한 Save ID나 계정 정보는 결과 파일에 기록하지 않았다.

### Grafana 대시보드 표시 검증

200문항 감사 행은 롤백했으므로 Grafana 표시 시험에는 **별도 `high_risk`
시험 이벤트 1건**을 로컬 MariaDB에 잠시 커밋했다. 현재 운영 중인 Grafana의
실제 대시보드 `kervion-security-audit`에서 사용하는 패널 SQL을 Grafana
데이터소스 API로 실행했다.

| 패널 | 저장 전 | 저장 후 | 시험 이벤트 삭제 후 |
| --- | ---: | ---: | ---: |
| `고위험 경고` | 0 | 1 | 0 |
| `최근 경고 메타데이터` | 0행 | 1행 (`high_risk`, `YB-1`, `secret_extraction`) | 별도 재조회 없음 |

Grafana 쿼리는 모두 HTTP 200으로 성공했다. 시험 이벤트는 요청 ID로 지정해
**해당 1건만 삭제**했다. 이는 대시보드의 실제 패널 쿼리와 MariaDB 연결을
검증한 결과이며, 브라우저 화면 렌더링이나 Discord 전송 확인은 아니다.

### 영구 저장된 200문항 결과의 대시보드 확인

사용자 요청에 따라 위 160건은 **삭제하거나 롤백하지 않았다.** 현재 실행 중인
Grafana 대시보드 `kervion-security-audit`의 실제 패널 SQL을 Grafana
데이터소스 API로 조회했다. 기본 24시간 범위에서 `경고 이벤트` **182건**,
`고위험 경고` **128건**이 표시되며, 기존 데이터도 포함된 수치다.
이번 시험 요청 ID 접두어로만 필터링하면 각각 **160건·114건**으로,
영구 저장된 시험 이벤트가 Grafana 데이터소스에 반영됨을 확인했다.
`최근 경고 메타데이터` 표는 최신 100건만 보여주므로 160건 전부가 한 번에
표시되지는 않는다. 수치는 조회 시점의 값으로 이후 다른 이벤트가 생기면 달라진다.

### Discord 웹훅 확인

Grafana에 `Input Guard high_risk detected` 알림 규칙과
`Kervion Discord Input Guard` Contact point를 등록했다. 처음 규칙은 시계열을
바로 비교해 `Error`였으나 **Reduce → Threshold**로 수정해 다시 적용했다.
고위험 시험 이벤트를 추가한 뒤 규칙은 `Alerting` 상태가 됐고,
Grafana 메트릭에 Discord 알림 요청 **1건**이 기록됐다.
별도로 같은 Grafana 컨테이너에서 설정된 Discord 웹훅에 비민감 시험 메시지를
보냈고 **HTTP 200과 메시지 ID**를 받았다. 선영이 Discord 채널에서
**세 메시지의 실제 표시**도 확인했다: (1) 수정 전 규칙의 `DatasourceError`,
(2) 수정 후 `Input Guard high_risk detected`의 `FIRING`, (3) `Spidey Bot`의
웹훅 연결 시험 메시지. 따라서 두 번째 메시지가 Grafana 고위험 알림의
전달 증거다. 첫 번째 오류 메시지는 정상 고위험 탐지로 세지 않는다.
고정 메시지가 오류 알림까지 ‘high_risk 감지’라고 설명하던 문제를 줄이기 위해
Contact point를 짧은 제목·본문으로 수정했다. 제목은 정상 고위험 알림이면
`🚨 입력 고위험 감지`, `DatasourceError`이면 `⚠️ 감시 데이터 조회 오류`로
구분하고, 본문은 관리자 대시보드 안내 한 줄만 표시한다. 알림을 발화시킨
별도 고위험 감사 이벤트 `ig_discord_b0cfacb4c390fb24`도 사용자 요청대로
DB에 남겼다.
