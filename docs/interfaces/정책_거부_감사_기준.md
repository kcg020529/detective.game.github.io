# 정책 거부 감사 이벤트 기준 (현재 구현안)

이 문서는 F 정책 판정의 결과를 H 감사 이벤트로 기록하고 O Grafana에 표시하는 **현재 구현 기준**이다. 팀의 최종 운영 기준은 아직 별도 합의가 필요하다.

## 언제 한 건을 기록하나

| 단계 | 기록 조건 | 기록하지 않는 경우 |
|---|---|---|
| `pre_search` | Planner의 회차·유형·장소·관련 AI 필터에 맞는 기록이 있고, 현재 Save·역할·Day·캐릭터에게 그 **대상 기록이 전부 접근 거부**된 경우. 구조화 필터가 없으면 전체 기록을 대상으로 판단 | 대상 중 허용 기록이 하나라도 있음, 대상 기록이 없음 |
| `post_search` | 검색 후보를 DB에서 재검증했을 때 실제 후보가 접근 거부된 경우 | 허용 후보만 있음, 후보 ID가 DB에 없음 |

요청의 같은 단계에서 거부한 기록이 여러 개여도 감사 행은 **한 건**이다. 구조화 필터가 없는 `pre_search`에서 전부 거부되면 검색을 진행하지 않아 같은 요청의 `post_search` 이벤트는 없다. 정상적인 일부 기록 필터링은 이벤트로 세지 않는다. 자유 문장만으로 특정 비공개 기록을 지목했지만 Planner가 구조화 필터를 만들지 않은 경우는 별도 정책 거부로 추측하지 않는다.

## 거부 사유

F의 `decide()`가 반환한 **첫 번째 적용 사유**를 집계한다. 검사 순서 때문에 미래 Day이면서 다른 AI의 기록이면 `FUTURE_DAY`로 집계된다.

| 코드 | 뜻 |
|---|---|
| `FUTURE_DAY` | Save의 현재 Day보다 나중에 공개될 기록 |
| `ROLE_DENIED` | 해당 역할의 공개 수준이 `metadata`·`summary`·`full` 중 하나가 아님 |
| `AI_SCOPE` | 해당 캐릭터가 알고 있거나 목격·청취한 기록이 아님 |

잘못된 메타데이터·권한 행 불일치·서버 상태 오류는 플레이어의 접근 거부가 아닌 **데이터/시스템 이상**으로 보아 이 이벤트에 넣지 않는다. 로그인 실패, 다른 사용자의 Save 접근, 검색 결과 없음(`no_match`)도 이 이벤트 범위 밖이다. ACL 시험 모드 `off`에서는 F 정책 검사를 하지 않으므로 이 이벤트가 생성되지 않는다.

## 저장 내용과 처리

- `event_type=policy_denial`, `level=deny`, `score=0`. 이 점수는 위험 점수가 아니라 기존 감사 테이블의 필수 숫자 필드를 채운 값이다.
- `signals_json={"stage":"pre_search|post_search","reasons":{"FUTURE_DAY":1,...},"denied_count":N}`. 사유별 건수의 합계가 `denied_count`다.
- 서버가 생성한 요청 ID, 발생 시각, 사용자·Save·역할·캐릭터 식별자를 기존 `audit_events`에 함께 저장한다.
- 질문·답변·기록 ID·요약·본문·비밀값은 저장하지 않는다.
- `continue_processing=true`는 기록을 제외하고 채팅 흐름을 계속한다는 뜻이다. 이후 답변 생성이 실패하면 감사 이벤트만 확정한다. 감사 저장 자체가 실패하면 조용히 무시하지 않고 요청을 실패시킨다.

Grafana의 **정책 거부 이벤트** 숫자는 감사 행 수(요청 단계 수)이며 거부된 기록 수가 아니다. **최근 정책 거부 사유** 표의 `denied_count`가 해당 행에서 제외된 기록 수다.
**정책 거부 사유별 집계** 표는 각 사유가 포함된 이벤트 수와 그 사유로 제외된 기록 수를 따로 보여 준다. 한 이벤트에 여러 사유가 있으면 사유별 이벤트 수의 합이 전체 이벤트 수보다 클 수 있다.
