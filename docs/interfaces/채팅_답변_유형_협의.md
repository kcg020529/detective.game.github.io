# 채팅 답변 유형 협의

- 상태: **협의 중 — 코드·DB 변경을 승인하거나 완료했다는 뜻이 아님**
- 작성일: 2026-10-26
- 제안자: 형주(D·G-2), 원문 「답변 종류 통일 요청.html」
- 목적: D 내부 처리 모드와 DB·API·프론트의 최종 답변 유형을 연결한다.
- 기준: 전달된 원문은 main `1039477`을 기준으로 작성됨. 이 문서는 원문의 제안과 현재 POST 구현, 용범 측 검토 의견을 구분해 정리한다.

## 1. 현재 구현에서 확인한 내용

1. DB `chat_messages.response_type`과 채팅 POST 검증은 `normal`, `partial`, `restricted`, `unknown` 네 값을 받는다. 사용자 메시지는 response_type이 NULL이다.
2. D 원문의 내부 모드는 `answer`, `unknown`, `restricted`, `off_topic`, `injection`이다. 답변 데이터는 `reply`, `used`이며 used는 내부 근거 번호다. 내부 모드와 최종 저장 유형은 같은 개념이 아니다.
3. 일부 기존 API 문서는 `reply_kind`, `redacted`, `access_denied`를 사용하므로 현재 DB·프론트·POST와 정합성을 맞출 필요가 있다.
4. G-1은 현재 allow/warn/high_risk 모두 계속 처리한다. 경고를 이유로 즉시 차단하거나 injection 모드로 전환하는 동작은 현재 계약에 없다.
5. POST는 `codex/chat-post-api`의 I04로 구현됐다. D·G-2 연결 전에는 503을 반환한다. 현재 상태에서 out_of_scope를 최종 답변 유형으로 반환하면 POST 검증을 통과하지 못한다.

## 2. 형주의 제안과 용범 측 검토 의견

| 항목 | 형주 제안 | 용범 측 검토 의견 | 합의 상태 |
|---|---|---|---|
| 최종 필드명 | response_type으로 통일 | 기존 DB·프론트·POST와 일치하므로 찬성 | 팀 확인 대기 |
| 최종 유형 | 기존 네 값에 out_of_scope 추가 | 범위 밖 안내를 unknown과 구분하므로 찬성 | 팀 확인 대기 |
| 범위 밖 안내 | D의 캐릭터별 고정 문구 | 추가 LLM 호출 없이 말투 유지 가능하므로 찬성 | 팀 확인 대기 |
| 입력 차단 안내 | off_topic·injection에 같은 문구 | 현재 G-1은 차단하지 않음. 차단 도입 여부·분기 주체를 먼저 협의해야 함 | 미확정 |
| partial 기준 | G-2가 실제 마스킹했을 때 | 찬성. summary·metadata 자료로 답했다는 이유만으로 partial을 붙이지 않음 | 팀 확인 대기 |

용범 측 의견은 이 대화에서 정리한 제안이며, 사용자나 팀 전체의 확정 결정을 대신하지 않는다.

## 3. 최종 유형 대응 제안

| D 내부 처리 | 최종 response_type 제안 | 조건 |
|---|---|---|
| answer | normal | G-2가 변경 없이 승인 |
| answer 등 생성 응답 | partial | G-2가 일부를 마스킹한 뒤 안전하다고 승인 |
| unknown | unknown | 아는 근거가 없어 모른다는 답변 |
| restricted | restricted | 서버가 접근 불가로 판정한 경우의 안전한 고정 안내 |
| off_topic | out_of_scope | 범위 밖 질문의 고정 안내 |
| injection | out_of_scope | 해당 분기를 사용하기로 별도 합의한 경우에만 적용 |

혼합 질문, 전체 출력 차단·대체, clarify의 최종 유형과 분기 우선순위는 아직 미확정이다. 검색 결과가 비었다는 사실만으로 restricted라고 단정하지 않는다. 권한 차단·AI가 모름·관련 기록 없음의 구분과 사용자에게 공개할 범위를 F·E·I·D가 합의해야 한다.

## 4. D·G-2와 I 사이 연결 제안

현재 [채팅 POST API](채팅_POST_API.md)는 다음 내부 연결부를 제안한다. D·G-2 담당자와 확정할 필요가 있다.

```python
draft = generator(question=question, context=context, history=history,
                  plan=plan, records=records)
final = output_guard(draft=draft, context=context, records=records)
# final: {"content": "최종 답변", "response_type": "합의된 유형"}
```

- D의 reply/used를 draft에 어떻게 담고 mode를 어떻게 전달할지는 미확정이다. used는 클라이언트에 노출하지 않는다.
- I는 E/F가 최종 허용한 기록만 D에 전달한다. records를 D의 memory=[{id, text}]로 바꾸는 규칙, history의 sender/content를 speaker/text로 바꾸는 규칙은 별도 합의한다.
- G-2는 안전한 최종 문장과 유형을 반환하고 검사 장애는 예외로 처리한다. I는 승인 전 초안을 사용자에게 반환하거나 대화 DB에 저장하지 않는다.
- 원문은 D의 캐릭터 ID를 YB-1~6으로 변경했다고 설명한다. 앞서 검토한 커밋 646ba2c는 AI-1~6이었으므로 연결 전 최신 브랜치에서 반영 여부를 확인한다.

| 담당 | 변경·검증 대상 |
|---|---|
| B·용범 | 004_chat_messages.sql CHECK, 기존 DB용 별도 이관 SQL·안내, 관련 문서 |

| F·용범 / E·찬규 | 허용 기록→memory 변환, 빈 결과·접근 불가 판단에 제공할 서버 신호 |
| I·공동, 현재 POST 용범 | 최종 유형 검증·변환·저장, API 계약 통일, history 변환, 회귀 검사 |

| G-1·선영 | 현재 계속 처리 설계 확인. 차단을 새로 도입하려면 별도 합의 |

담당자 확인 없이 다른 파트 코드·PLAN·RESULT를 변경하지 않는다. 과거 RESULT는 당시 결과로 보존하고, 새 변경은 새로운 실제 수행 기록으로 남긴다.
