# 역할별 게임 기록 공개 정책

> 갱신일: 2026-10-26 · 상태: **사용자 확정 정책 · 적재/스키마 구현 · 실제 DB/서버 적용 전**
> 기준: `MASTER.md` §5, `PARTS.md` F
> 주 담당: F(용범) · 연계: A·B·E·I
> 범위: 여섯 실험 기록의 역할별 공개 수준. 계정 인증·게임 상태 변경 API의 세부 정책은 별도다.

## 1. 기록 종류 × 역할 공개 수준

판정 단위는 JSON 파일 전체가 아니라 `(dataset, record_id)`로 구분하는 기록 한 건이다. 같은 파일 안의 기록도 각각 판정한다.

| 기록 종류 | `std` 학부 연구생 | `grad` 대학원생 | `prof` 교수 |
|---|---|---|---|
| `Setup` 환경 | `full` | `full` | `full` |
| `Action` 행동·목격 | `summary` | `summary` | `full` |
| `Dialogue` 대화 | `metadata` | `summary` | `full` |
| `Thought` 속마음 | `deny` | `deny` | `summary` |
| `Result` 실험 결과 | `summary` | `full` | `full` |
| `Incident` 이상행위 | `deny` | `metadata` | `summary` |

이 표를 기록별 `document_permissions` 행을 작성·검수하는 기준으로 사용한다. 저장 키는 기존 `(dataset, record_id, role)`을 유지한다. 역할 이름의 순서로 권한을 상속하거나 비교하지 않는다.

런타임에서 권한 행이 없으면 `deny`다. 누락된 행을 위 표나 레거시 `allowed_roles`로 보충하지 않는다. 기록별 예외가 필요하면 정책 변경과 검수를 거쳐 권한 행에 명시하며, Planner나 LLM이 예외를 만들 수 없다.

`Setup`의 모든 역할 `full`은 역할에 따른 필드 제한을 없앤다는 뜻이다. 현재 Day·선택 AI 지식 범위·Save 소유권 검사는 계속 적용한다. `Thought`는 현재 표에서 교수에게 요약만 허용하며 다른 두 역할에는 존재·ID도 제공하지 않는다.

## 2. 네 공개 수준과 허용 필드

공개 메타데이터는 `record_id`, `record_type`, `test_id`, `day`, `location_ids`, `involved_ai`와 해당 유형의 `witness_ai`·`overheard_ai`다. Action·Dialogue 외 유형에 관찰 관계 필드를 새로 요구하지 않는다.

| 공개 수준 | Context·응답에 포함할 수 있는 필드 |
|---|---|
| `deny` | 없음. 기록 존재·ID도 제공하지 않음 |
| `metadata` | 공개 메타데이터만 |
| `summary` | 공개 메타데이터 + `summary` |
| `full` | 공개 메타데이터 + `summary` + `content` |

서버가 인가에 사용하는 메타데이터와 사용자에게 공개하는 메타데이터는 구분한다. 권한 테이블·내부 정책 사유·Save 소유자 등의 내부 속성을 이름이 메타데이터라는 이유로 공개하지 않는다. 공개 필드는 허용 목록으로 선택한다.

`summary`와 `metadata`도 내용·참여자·장소를 통해 추리 단서를 드러낼 수 있으므로 공개 수준에 맞는 콘텐츠 검수가 필요하다. 원문을 모델에 전달해 요약하게 만든 뒤 `summary` 권한을 만족했다고 처리하지 않는다. Setup 본문의 AI별 초기 위치는 `content`이므로 `full`에서만 제공한다.

기존 `basic_metadata`는 새 정책에서 사용하지 않는다. 새 `metadata`는 기존 `metadata`의 공개 필드를 유지한다. 기존 `basic_metadata` 행을 그대로 `metadata`로 치환하면 AI 관계·장소가 추가 공개되므로 자동 치환하지 않고 기록별 재검수 후 이관한다.

## 3. 공개 수준과 함께 확인할 조건

역할 공개 수준이 `full`이어도 아래 조건을 모두 만족해야 한다.

1. 인증된 사용자와 요청 Save의 소유권을 서버가 확인한다.
2. 역할과 현재 Day는 해당 Save의 `role`, `day`를 사용한다. 사용자 문장·요청 본문·Planner의 주장을 권한 증명으로 사용하지 않는다.
3. 대상 기록은 `record.day <= Save.day`여야 한다. 별도 `release_day`를 추가하지 않는다.
4. 선택 AI가 해당 정보를 아는 근거 관계를 확인한다. 행동 주체·목격자, 대화 참여자·엿들은 AI, Thought 소유 AI 등의 관계를 사용한다. 전달받은 지식에는 근거 기록이 필요하며, 구체적인 유형별 판정은 A·B 데이터 계약과 맞춘다.
5. 정적 게임 기록은 공통 콘텐츠로 다루고, Save 전용 데이터는 현재 사용자가 소유한 Save 범위에 한정한다. 정적 기록에 미구현 Save 필드가 이미 있다고 가정하지 않는다.
6. 해당 기록·역할의 `document_permissions`를 확인하고 공개 수준에 맞는 필드만 선택한다. 알 수 없는 역할·종류·공개 수준, 필수 인가 정보 누락, 정책 확인 실패는 기본 거부한다.

게임의 비밀이라는 이유만으로 별도 차단하지 않는다. 위 조건과 공개 수준을 만족하는 단서는 정상적으로 발견할 수 있어야 한다.

## 4. 검색 및 Context 연동

1. F는 서버 상태에서 산정한 허용 조건을 E에 제공하고, E는 Qdrant 검색 전에 ACL 필터로 강제한다. 필터의 구체적인 필드·직렬화 형식은 B·E·F 연동 시 정한다.
2. Qdrant가 반환한 `(dataset, record_id)`로 MariaDB 원본과 권한을 다시 확인한다. Qdrant payload 자체는 최종 인가 근거가 아니다.
3. 재검증을 통과한 기록을 공개 수준별 필드로 투영한 뒤 캐릭터 모델 Context에 넣는다. 권한 밖 원문을 넘긴 뒤 출력에서 가리는 것은 허용하지 않는다.
4. 빈 검색 결과·검증 오류·검색 장애가 발생해도 전체 데이터로 대체하지 않는다. 검색 단계·Context 전달 단계·최종 출력의 노출을 각각 검증한다.

## 5. 정책 검증 기준

| 상황 | 기대 결과 |
|---|---|
| 공통 조건을 만족하는 Setup | 세 역할 모두 본문까지 허용 |
| 공통 조건을 만족하는 std의 Action | 요약까지 허용, 본문 제외 |
| 공통 조건을 만족하는 grad의 Action | 요약까지 허용, 본문 제외 |
| 공통 조건을 만족하는 std의 Dialogue | 메타데이터만 허용 |
| std·grad의 Thought | 기록 존재·ID·요약·본문 미제공 |
| 공통 조건을 만족하는 prof의 Thought | 요약까지 허용, 본문 제외 |
| std의 Incident | 기록 존재·ID·요약·본문 미제공 |
| 공통 조건을 만족하는 grad의 Incident | 메타데이터만 허용, 요약·본문 제외 |
| 공통 조건을 만족하는 prof의 Incident | 요약까지 허용, 본문 제외 |
| 미래 Day·선택 AI가 모르는 기록·타인 Save | 역할 공개 수준과 관계없이 거부 |
| 권한 행 누락·미등록 공개 수준·정책 오류 | 기본 거부, 표 기반 런타임 fallback 금지 |
| 요청에서 역할·Day·소유권 사칭 | 서버 상태 유지, 권한 확장 금지 |

여섯 종류 × 세 역할의 18개 조합은 적재 도구 단위 테스트에서 확인한다. Day·AI Scope·Save 등의 복합 접근 조건과 서버 강제는 후속 F/E 테스트가 필요하며, 적재 테스트 통과가 접근통제 완료를 의미하지 않는다.

## 6. 기존 구현과 이관 과제

- `database/policies/game_record_permissions.json`에 위 표를 저장했고, 적재 도구는 기록마다 세 역할의 공개 수준을 생성한다. 검수한 원본의 role_permissions가 있으면 이를 우선하며 빠진 역할은 deny다. JSON 원본의 allowed_roles는 game-data 인가에 사용하지 않는다.
- `006_document_permissions.sql`과 로더는 4단계만 허용한다. game-data에 단일 disclosure_level·--default-disclosure를 적용하면 오류다. 명시적 단일 수준 형식은 합성 test-data에만 남긴다.
- 기존 5단계 DB용 `database/migrations/mariadb/001_disclosure_levels_v2.sql`은 basic_metadata를 deny로 낮추고 CHECK를 교체한다. 이후 검수한 기록을 재적재해 표를 적용한다. 실제 DB 이관·적재는 미검증이며 [이관 안내](../../database/migrations/README.md)를 따른다.
- 서버 Policy Engine, Qdrant 필터, 원본 재검증, 필드 투영 및 API 연결은 후속 구현이다. `rules.json`의 공통 규칙과 캐릭터·지도 자료는 이 여섯 기록 표의 적용 대상으로 자동 간주하지 않으며 별도 공개 계약을 정한다.
