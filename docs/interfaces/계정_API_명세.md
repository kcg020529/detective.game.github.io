# 계정 API (회원가입 · 로그인 · 로그아웃)

2026-10-23 / J(프론트) 작성 / I(선영) 확인 부탁드립니다

관련 DB: `database/schemas/mariadb/002_users.sql`, `005_user_roles.sql`
기존 계약: [API 요청·응답 계약](API_요청응답_계약.md)

프론트는 서버 요청을 전부 `frontend/play/api.js` 한 곳에서 보냅니다. 지금은 그 안의 가짜 데이터(Mock)로 돌아가고 있고, 서버 주소만 넣으면 실제 서버로 붙도록 해 두었습니다. 그래서 아래 경로와 응답 모양만 맞춰 주시면 프론트는 따로 고칠 게 없습니다. `api.js`는 수정하지 않으셔도 되고, 서버 코드만 따로 만드시면 됩니다. 바꾸고 싶은 부분이 있으면 말씀해 주세요. 프론트를 맞추겠습니다.

## 1. 요청 목록

공통: `/api/v1` 아래, JSON, 필드 이름은 snake_case

| 요청 | 보내는 것 | 성공 | 실패 |
|---|---|---|---|
| `POST /auth/signup` | `username`, `password`, `role` | 201, `{ user_id, username, roles }` + 쿠키 | 409 아이디 중복 / 422 형식 오류 |
| `POST /auth/login` | `username`, `password` | 200, `{ user_id, username, roles }` + 쿠키 | 401 아이디나 비밀번호 틀림 |
| `POST /auth/logout` | 없음 | 204 (본문 없음) | - |

`roles`는 배열입니다. 예: `["std"]`

`roles`는 가입 시 선택한 역할 등을 새 게임 화면의 기본값으로 참고하는 정보이며 선택 권한 목록이 아닙니다. 새 게임은 세 역할 중 자유롭게 고르고, 생성 후에는 서버에 저장된 `saves.role`을 해당 Save의 고정 역할로 사용합니다.

### 회원가입

화면에서 아이디, 비밀번호, 비밀번호 확인을 입력하고 다음을 누르면 역할 카드를 고르는 화면으로 넘어갑니다. 거기서 하나를 고르면 그때 요청을 한 번 보냅니다.

- `role`은 `prof` / `grad` / `std` 중 하나입니다. 역할은 난이도 개념이라(교수 쉬움, 대학원생 보통, 학부 연구생 어려움) 따로 잠그는 건 없습니다. 새 게임을 만들 때 아무 역할이나 다시 고를 수 있고, 가입 때 고른 역할은 새 게임 화면에서 처음에 선택되어 있도록만 씁니다.
- `users`에 한 줄, `user_roles`에 `(user_id, role)` 한 줄을 넣으면 됩니다. 둘이 같이 들어가야 하니 트랜잭션으로 묶어 주세요.
- 비밀번호 확인 칸이 맞는지는 프론트에서 먼저 확인하므로 서버는 `password`만 받으면 됩니다.
- 가입이 끝나면 바로 로그인된 상태로 넘어갑니다. 그래서 가입 응답에도 쿠키를 같이 내려 주셔야 합니다.
- 아이디는 앞뒤 공백을 자르고 1~50자입니다. `users.username`이 VARCHAR(50)이고, 테이블 설정상 대소문자는 같은 것으로 취급됩니다.
- 비밀번호는 `password_hash`에 해시로만 저장합니다. 길이 제한을 정해서 알려 주시면 화면 안내 문구를 맞추겠습니다. bcrypt를 쓰시면 72바이트를 넘는 부분은 잘린다는 점만 참고해 주세요.

### 로그인

- 아이디가 틀렸는지 비밀번호가 틀렸는지는 구분하지 말고 401 하나로 보내 주세요.
- `roles`는 `user_roles`에서 읽어 옵니다. 없으면 `[]`로 보내셔도 됩니다.
- 로그인할 때마다 세션 값은 새로 만들어 주세요. 예전 값을 재사용하면 안 됩니다.

### 로그아웃

- 서버 세션을 지우고, 쿠키도 `Max-Age=0`으로 만료시켜 주세요.
- 이미 로그아웃된 상태에서 불러도 204를 주시면 됩니다.

## 2. 쿠키, CORS, 오류 형식

### 쿠키

프론트는 토큰을 따로 들고 있지 않습니다. 서버가 쿠키를 내려 주면 브라우저가 알아서 같이 보내는 방식입니다 (`credentials: 'include'`). 응답 본문에 토큰을 넣을 필요는 없습니다.

```
Set-Cookie: kervion_session=<랜덤값>; HttpOnly; Secure; SameSite=Lax; Path=/api/v1; Max-Age=...
```

- `HttpOnly`는 꼭 넣어 주세요. 이게 있어야 페이지에서 스크립트로 쿠키를 읽어 가지 못합니다.
- `Secure`는 HTTPS에서만 보내지는 옵션이라 로컬(`http://127.0.0.1`)에서 테스트할 때는 빼야 합니다.
- 쿠키 값은 추측할 수 없는 랜덤값으로 하고, 사용자 정보는 서버 세션 쪽에 두면 됩니다. 세션을 어디에 둘지(메모리/DB/Redis)와 만료 시간은 정해지면 알려 주세요.
- 다른 사이트에서 몰래 요청을 보내는 것을 막기 위해, POST 요청은 `Origin` 헤더가 허용한 주소인지 한 번 확인해 주세요.

### CORS

프론트는 GitHub Pages(`https://kcg020529.github.io`)에 올라가 있고 서버는 주소가 다르기 때문에 CORS 설정이 필요합니다. 쿠키를 같이 보내기 때문에 `*`는 쓸 수 없고 주소를 정확히 적어야 합니다.

```
Access-Control-Allow-Origin: https://kcg020529.github.io
Access-Control-Allow-Credentials: true
Access-Control-Allow-Methods: GET, POST, PUT
Access-Control-Allow-Headers: Content-Type
```

로컬에서 테스트할 때는 `http://127.0.0.1:8010`(프론트를 띄우는 주소)도 같이 허용해 주세요.

한 가지 걸리는 점이 있습니다. 프론트(github.io)와 서버 도메인이 완전히 다르면 브라우저가 `SameSite=Lax` 쿠키를 보내지 않을 수 있습니다. 서버 주소가 정해지면 같이 한번 확인해 봤으면 합니다. 안 되면 `SameSite=None; Secure`로 바꾸고 Origin 확인은 꼭 켜 두면 됩니다.

### 오류 응답

실패할 때는 이 모양으로 보내 주세요.

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "아이디는 50자 이하로 입력해 주세요.", "request_id": "req_01" } }
```

`message`는 화면에 그대로 뜨기 때문에 사용자에게 보여 줄 한국어 문장으로 써 주세요.

| 상태 | code | 언제 | 화면에서 |
|---|---|---|---|
| 401 | `AUTH_REQUIRED` | 로그인 실패 | 로그인 화면에 message 표시 |
| 409 | `STATE_CONFLICT` | 가입할 때 아이디 중복 | 아이디 칸 밑에 "이미 있는 아이디입니다." |
| 422 | `VALIDATION_ERROR` | 빈 값, 너무 긴 값, 없는 역할 | 아이디 칸 밑에 message |
| 503 | `SERVICE_UNAVAILABLE` | DB 연결 실패 등 | 잠시 후 다시 시도 안내 |

로그인 실패 문구는 `"아이디 또는 비밀번호가 맞지 않습니다."` 정도면 될 것 같습니다.

## 4. 프론트와 붙여 보기

서버를 띄운 뒤 `frontend/index.html`에서 `api.js`를 불러오는 줄 바로 위에 아래 한 줄을 넣으면 됩니다.

```html
<script>window.KERVION_API_BASE = 'http://127.0.0.1:8000/api/v1';</script>
```

아래 순서로 확인해 보시면 됩니다: 계정 만들기 → 역할 고르기 → 정문(로비)에 들어가지는지 → 로그아웃 → 같은 아이디로 로그인 → 비밀번호를 틀리게 로그인(문구 확인) → 같은 아이디로 다시 가입(중복 문구 확인)

참고로 프론트는 로그인이나 가입이 성공하면 바로 Save 목록(`GET /saves`)을 불러온 뒤 정문으로 넘어갑니다. 이 요청이 서버에 없으면 정문으로 넘어가지 못하고 오류가 뜹니다. 테스트할 때만 `GET /saves` → `200 { "saves": [] }`를 임시로 하나 만들어 두시면 끝까지 확인할 수 있습니다. Save API는 따로 정리해서 드리겠습니다.
